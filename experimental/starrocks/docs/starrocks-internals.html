Work on top of StarRocks

A self-contained tour of the experimental/starrocks compute-node codebase: who owns what, how a query lives today, where the architecture still has a hole, and a learn-by-doing ladder to close it.

Governing idea: StarRocks owns everything distributed. Sirius executes one fragment at a time and never knows it is distributed. The Rust wrapper moves bytes between them.

03 · The hole in the middle

Biggest structural gap

The CN already speaks StarRocks protocols and can translate + buffer a RESULT_SINK fragment. What it cannot do is turn the FE’s multi-fragment plans into a distributed GPU pipeline.

Implemented

Today’s path

  • 1FE registers CN (MySQL + heartbeat)
  • 2BRPC exec_plan_fragment
  • 3PlanTranslator → Substrait
  • 4StubExecutor materializes
  • 5ResultStore + fetch_data
Structural gap
Fragment-boundary streaming surface source · sink · session · nixl · shared memory
Proposed · #836–#840

Target path

  • 1FE plans multi-fragment + routes
  • 2Streaming sink / source at boundaries
  • 3Stream session push / pull / EOS
  • 4Nixl (or local handle hand-off)
  • 5Shared cuCascade budget (#840)
Thesis in one sentenceThe CN has FE registration and a complete single-fragment RPC loop, but it still lacks the fragment-boundary streaming surface (source / sink / session) and wrapper-owned exchange (nixl + memory accounting) that turn FE multi-fragment plans into a distributed GPU pipeline — without which TPC-H across CNs cannot run.
Missing pieceIssueWhy it blocks
Streaming source#836Intermediate fragments have nowhere to accept exchange input
Streaming sink#837No incremental GPU-resident output; RESULT_COLLECTOR materializes
Partitioned sink / backpressure#838Shuffle joins/aggs need hash-partitioned multi-dest channels
Stream session#839No push/close/pull API; no edge-triggered re-arm
Shared resource budget#840Exchange buffers invisible to downgrade → OOM under pressure
Nixl agentMatthijsNo cross-CN GPU-direct transport
Translator EXCHANGE_NODEF8v1 only scan/filter/project — cannot express exchange fragments

Also incomplete on today’s path

  • FragmentExecutor is sync and fully materializing
  • Non-RESULT_SINK fragments translate-only (no buffer)
  • Translator: no joins, aggs, sorts, exchange
  • FFI: only make_context* on dev
  • Engine context in main not yet threaded into the executor

What already works

  • CN registration + sticky heartbeat identity
  • PRPC framing without linking C++ BRPC
  • Thrift → Substrait for scan/filter/project
  • fetch_data drain of buffered MySQL-text rows
  • get_file_schema for FILES() parquet
04 · How to change the system

Design map: change vs add

Before writing code, decide which column you are in. Mixing them is how reviews stall and ownership blurs.

Change an internal

Touch existing contracts carefully

  • Hints / task creator — src/creator/, get_next_task_hint
  • Pipelines / SCHED-RR — reservation defines device
  • Downgrade / spill — only idle batches in registered repos
  • Plan generator — unwired ops silently fall back to CPU
  • Translator nodes — preserve flat-preorder + ensure_consumed
Add a new component

Prefer ordinary operators + channels

  • #836/#837 — subclass sirius_physical_operator
  • exchange_channel — bounded handle queue (net-new)
  • Stream session — owns channels + repos + re-arm
  • Translator arms — match + children-first + row layout
  • FragmentExecutor impl — inject into CN service
Keep outside Sirius core

Wrapper / FE territory

  • Partition routing and fragment creation (FE)
  • Nixl agent threads and staging arena (wrapper)
  • PRPC / Thrift wire protocols (wrapper)
  • Cross-CN EOS sender counts (session + plan meta)
  • Theseus-style worker sync algorithms — out of scope
Push into cuCascade when agnostic

Engine-agnostic substrate

  • data_batch lock states, repositories, reservations
  • Shared memory_reservation_manager (#840 option A)
  • Grow FFI toward standalone libsirius
  • DuckDB becomes a thin shim — same embedding surface

Operator touch points (standalone PR discipline)

  1. Enum + ToString in sirius_physical_operator_type
  2. Header/impl under src/include/op/ + src/op/
  3. CMake EXTENSION_SOURCES + explicit TEST_SOURCES
  4. Unit tests construct the op directly — no plan wiring yet
  5. Docs entry in docs/super-sirius/operators.md
  6. Do not stack on Matthijs’s #1021–#1024; wiring is a later follow-up

Translator “adding a node” checklist

1. Match arm in translate_plan_node / translate_expr_node
2. Translate children first; build Substrait relation/expr
3. Set row_tuples + output_width (multi-input = L→R concat)
4. Register extension functions via ExtensionRegistry
5. Preserve flat-preorder cursor + ensure_consumed
Templates to imitateSource #836 ← GPU_SCAN + split_connector::is_closed (closed AND drained). Sink #837 ← CONCAT boundary shape (is_source && is_sink), gating on channel capacity — not RESULT_COLLECTOR (that materializes and special-cases finalize).
